\noindent\textbf{Static Analysis and Checker Languages.}\quad
Path-sensitive analyzers, abstract interpreters and symbolic engines provide guards, states, paths and diagnostics~\cite{engler2001bugs,ball2002slam,cousot2005astree,cadar2008klee}, with industrial deployments~\cite{calcagno2015infer,bessey2010coverity,sadowski2015tricorder}. Relational frameworks query program facts through rules and points-to specifications~\cite{avgustinov2016ql,jordan2016souffle,bravenboer2009doop}; semantic patching encodes recurring systems-code transformations~\cite{padioleau2008coccinelle}. \toolname introduces no analyzer or query language: it edits LLM-generated checkers using analyzer-native facts for semantic completion.

\noindent\textbf{Vulnerability Detection and Patch Evidence.}\quad
Static vulnerability detection has long used taint and data-flow reasoning~\cite{livshits2005finding,jovanovic2006pixy,arzt2014flowdroid}, graph and AST representations~\cite{yamaguchi2014cpg,yamaguchi2012vex}, and learning-based token-, slice-, and line-level models~\cite{russell2018vulnerability,li2018vuldeepecker,li2021sysevr,fu2022linevul}, though datasets and evaluations show that semantic robustness remains difficult~\cite{fan2020bigvul,chakraborty2021deep}.  Clone- and patch-driven systems use historical fixes as compact witnesses~\cite{jang2012redebug,li2016vulpecker,kim2017vuddy}.  These motivate our use of patches as specifications, but \toolname targets a different artifact: an already generated checker whose fixed-side behavior reveals missing semantics.

\noindent\textbf{LLM-Based Code and Security Reasoning.}\quad
Code LLMs synthesize programs~\cite{chen2021codex}, and agents such as RepoAudit audit repositories~\cite{guo2025repoaudit}. LLMDFA decomposes compilation-free dataflow analysis and uses synthesized tools for extraction and feasibility checks~\cite{wang2024llmdfa}. Generated artifacts still require security validation~\cite{pearce2022copilot,perry2023users,khoury2023chatgpt}. \toolname edits a static-analysis artifact; paired analyzer executions, not the model's explanation, determine acceptance.

\noindent\textbf{Checker Synthesis and Feedback-Guided Repair.}\quad
Patch-driven checker synthesis, especially KNighter~\cite{yang2025knighter}, is the closest prior work. LLMs transform historical security fixes into specialized analyzers that compile, execute, and are reused.  \toolname is complementary because it assumes such a detector exists and refines it post-synthesis. A generator's validation feedback reveals which side a detector fires on but not whether the missing predicate is a guard, barrier, flow, state, lifetime, type filter, or API-usage relation.

The loop also relates to repair, synthesis and counterexample-guided workflows using compiler/test/verifier feedback~\cite{clarke2000cegar,solarlezama2006sketch,legoues2012genprog,kim2013par,long2015spr,nguyen2013semfix,mechtaev2016angelix,long2016prophet}, and iterative LLM feedback, tool use and search~\cite{madaan2023selfrefine,shinn2023reflexion,yao2023react,schick2023toolformer,yao2023tree}. Here the edited artifact is a detector, not the vulnerable program. Paired execution retains warning recovery or report reduction with vulnerable warning presence, not compilation or suppression alone; this does not prove target detection.

\noindent\textbf{Analyzer Context for LLMs and Alert Triage.}\quad
LLift combines static analysis and LLMs for post-constraint-guided use-before-initialization reasoning~\cite{li2024llift}. Chapman et al. interleave intermediate results and prompts to infer error specifications~\cite{chapman2024interleaving}; IRIS infers taint specifications and analyzes CodeQL context~\cite{li2025iris}. LLM4PFA filters reports through interprocedural feasibility reasoning~\cite{du2025llm4pfa}, and ZeroFalse enriches alerts before LLM adjudication~\cite{iranmanesh2025zerofalse}. VulGenie combines patch-dependency and attack/defense value-flow analysis with LLM-assisted API-rule synthesis and adaptive Java detection~\cite{chen2026vulgenie}. We claim neither first use of analyzer information nor new path-feasibility reasoning. Our operation completes an existing checker using auditable analyzer and checker context with paired warning outcomes, not a universal causal or precision claim. Evidence origin, selected edits, failed attempts and scope remain inspectable.
