Static vulnerability checkers encode conditions that distinguish unsafe code from safe uses of the same operations. Industrial analyzers demonstrate their value~\cite{engler2001bugs,bessey2010coverity,calcagno2015infer,sadowski2015tricorder}, but checker authoring requires domain knowledge and familiarity with the analysis framework. Patch-driven synthesis generates a detector from a historical fix. KNighter~\cite{yang2025knighter} generates CSA checkers and refines them using compilation, reports and validation on vulnerable and fixed revisions.

An apparently small checker defect can lie between the source-level mechanism and the backend representation: a cleanup attribute names a lowered callback, a location callback supplies a cast-wrapped expression, or a state lookup uses a different region from its update. Patch, source and ordinary reports can support debugging, but need not make the relevant mismatch explicit. Conversely, recognizing the backend representation does not establish the guard, object identity or owning-scope condition needed for a valid warning. This distinction matters when refinement is accepted using warning presence rather than an independently validated diagnosis.

\begingroup\emergencystretch=2em
\toolname adds bounded, provenance-labelled analyzer context to post-synthesis editing. Compiler representations and observations of checker execution supplement the patch, source and ordinary validation feedback. The approach builds on iterative feedback-guided refinement~\cite{madaan2023selfrefine,shinn2023reflexion}; it does not introduce checker editing or paired validation, which KNighter already performs. Its technical focus is the additional compiler/checker observation interface and explicit accounting for origin, scope and unavailable evidence. CSA and CodeQL offer different representations~\cite{clangsaDocs,avgustinov2016ql,codeqlDocs}; only records with retained backend-produced payloads and bindings count as analyzer-internal evidence.
\par\endgroup

We evaluate the resulting workflow and the validity of its apparent improvements. All 39 selected generated-only CSA checkers enter KNighter's actual loop and both \toolname variants. Native reaches 23 warning-positive vulnerable revisions versus KNighter's 15, but KNighter's report-driven policy makes no recovery edit on the 24 initially silent inputs. No-internal already reaches 21. Native and no-internal have nearly tied version-level $F_1$, with 123 versus 68 fixed-side reports. The complete preexisting 15-case noisy stratum instead has 44 native fixed reports versus KNighter's 69, concentrated in G24. These are distinct coverage and burden outcomes, not interchangeable measures of target detection.

We then connect all 11 non-tied comparisons to actual checker edits and scoped source/path evidence. Four frozen source-derived perturbation suites test selected mechanisms; three paired next-decision draws at each of two checkpoints examine selected native clues. These analyses expose both useful repairs and residual obligations: cleanup recognition can activate a wrong-scope state machine, and sink recognition can recover a target-line warning on a non-NULL path. The resulting contribution is an implementation-grounded account of when an observed refinement supports a target claim, rather than a claim that more analyzer context is uniformly better.

Our contributions are:
\begin{itemize}
  \item A refinement workflow exposing bounded compiler/checker observations with explicit provenance, source binding and missingness, while keeping model edits and programmatic validation distinguishable.
  \item A complete comparison of 39 checkers using KNighter's actual loop and both context variants, with repeated subjects, model configurations and a separate backend example.
  \item An evidence-linked analysis of the complete non-tie subset and selected interventions, separating recognition repairs, supported target obligations and report burden. This analysis provides concrete counterexamples to treating warning recovery or target-line agreement as semantic validation.
\end{itemize}
The study is patch-local and selected rather than population-representative. Its source/path interpretations, controlled models and additional phases are reported separately; they do not establish target-recall rates, a predictive evidence selector or broad semantic generalization.
