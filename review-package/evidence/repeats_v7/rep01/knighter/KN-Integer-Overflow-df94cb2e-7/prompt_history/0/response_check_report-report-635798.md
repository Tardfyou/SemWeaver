Pre-patch, `max_sectors` is only `unsigned` (at most `2^32 - 1`), and its initializer also uses `~0`, an `int`-width mask, rather than a 64-bit mask. Consequently, the aligned sector limit is computed/truncated at 32-bit width before it is used in the extent-splitting calculations. The post-patch-style correction is to use `u64 max_sectors` and a 64-bit all-ones mask (`~0ULL << c->block_bits`), preserving the sector count through the alignment, comparison, and key-resize path.
