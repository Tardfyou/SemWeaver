- Decision: NotABug
- Reason: `utf16_path` is freed at `out_free_path` before the retry branch, but every path back to `replay_again` next assigns a fresh result to `utf16_path` before it can reach cleanup again. If conversion fails, the assignment sets it to `NULL` and the function returns immediately. The reported pointer therefore cannot be freed twice on this replay path. This differs from the target pattern, where an early error can reach shared cleanup before the pointer is reallocated. The patch confirms the distinction: it resets `ea` before the retry iteration’s possible early cleanup; it does not change `utf16_path`, whose retry assignment already replaces the freed value.
