- Decision: Bug
- Reason: The pre-patch loop ran with `i < MAX_PIPES * 2` while the body could read `dc->links[i + 1]`. With 12 link slots, iteration `i == 11` could therefore read `dc->links[12]`, outside valid indices 0–11, when that slot held a USB4 DPIA link and its computed host-router index matched `hr_index`. The patch changes the bound to `i < (MAX_PIPES * 2) - 1`, so the largest accessed look-ahead index is 11. This is the target off-by-one pattern and the fix directly addresses it. The report’s annotated source already shows the patched bound, so the warning does not apply to that displayed version; it identifies a real bug in the pre-patch code.
