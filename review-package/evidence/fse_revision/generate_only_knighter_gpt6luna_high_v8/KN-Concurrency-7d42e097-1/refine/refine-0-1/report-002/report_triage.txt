- Decision: NotABug
- Reason: The report’s specific warning is false positive: the shown worker already has the `completion_done()` guard at lines 158–162. In async mode, the worker frees the context and the submitter does not wait on or free it. In sync mode, the worker either frees it if the completion is already done, or completes it so the waiting submitter can free it. The pre-patch code did have the target UAF pattern: on a timed-out sync wait, the submitter freed `reset_data` while the queued worker could still access it. The patch removes that timeout-path free, so the reported UAF is not present in the shown code.

  There is a separate concern in the patch’s timeout path: `completion_done()` reports whether the completion has been signaled, not whether a waiter timed out. If the submitter times out, it leaves `reset_data` allocated; the worker will ordinarily see the completion as not done and call `complete()` rather than free it. That appears to risk a leak, not the reported UAF.
