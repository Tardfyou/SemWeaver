- Decision: NotABug
- Reason: The allocation uses `num_devices * sizeof(...)` before calling `kvzalloc`, so it matches the target pattern syntactically. But here `num_devices` comes from `p->n_pdds`, the process’s internal count of GPU devices, not directly from a userspace count. On a 64-bit kernel, `num_devices` is `uint32_t`, so even its maximum value multiplied by a kernel object’s `sizeof` cannot overflow `size_t`. On 32-bit, overflow would require an unrealistically large device count; KFD’s device count is bounded by the GPUs available to the system. Thus the report does not demonstrate a feasible undersized allocation followed by an out-of-bounds access.
